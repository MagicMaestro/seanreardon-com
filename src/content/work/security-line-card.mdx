This shipped in 2016 as a customer-facing vendor comparison matrix for a security products line card — pick up to five vendors, compare features, drill into hardware vs. software vs. cloud. That was the surface.

The actual problem it solved was internal: we were mid-migration to a new VOIP phone system. Team extensions were changing weekly. Reps fielding customer questions about specific vendors needed to know who to transfer the call to *today*, not last week. Static documentation went stale faster than anyone could update it.

So under the comparison UI was a JSON file that mapped every vendor and product category to a current contact. The matrix's hover state surfaced that contact in real time. Updating extensions meant editing one JSON object — no deploys, no developer in the loop. Reps could keep the file accurate themselves. Customer-facing the tool looked like a feature matrix; internally it was a self-maintaining routing layer for a phone tree that wouldn't sit still.

Stack was deliberately small — vanilla JS pulling from JSON, dropdowns for vendor selection, CSS Grid for the matrix layout. The interesting design move was where to put the contact info: hover-on-cell rather than a separate panel, so the rep's eye-trace was vendor → category → contact in one motion. The phone migration finished a few months later and the JSON file got smaller, but the pattern — one-file routing layer surfaced through a customer feature — stayed useful for a while.
